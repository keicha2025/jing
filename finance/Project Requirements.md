\<技術說明\>  
資料結構 (Schema)  
建立四個主要集合：users (使用者設定), holdings (目前持股), monthlyConfigs (配置模板), 以及 snapshots (歷史快照)。  
1\. users (集合)  
儲存使用者的個人化偏好與手動匯率。  
Document ID: {userId} (與 Google Auth 的 UID 一致)  
Fields:  欄位：  
code  
JSON  
{  
  "email": "user@example.com",  
  "displayName": "Jing",  
  "baseCurrency": "TWD",          // 主要計算幣別  
  "manualExchangeRates": {        // 手動輸入的匯率  
    "USD": 32.1,  
    "JPY": 0.21,  
    "TWD": 1  
  },  
  "categories": \["美股", "台股", "基金", "其他"\], // 自定義類別清單  
  "financialGoal": 10000000,      // 理財目標總額  
  "createdAt": timestamp,  
  "lastSyncAt": timestamp         // 最後點擊「同步股價」的時間  
}  
2\. holdings (集合)  
儲存「目前」的資產狀況（存量），用於計算目前的資產分佈。  
Document ID: 自動生成 或 {userId}\_{ticker}  
Fields:  欄位：  
code  
JSON  
{  
  "uid": "{userId}",  
  "ticker": "2330.TW",            // 股票代號 (支援 Yahoo Finance 格式)  
  "name": "台積電",                // 可由 API 自動抓取存回  
  "category": "台股",  
  "shares": 500,                  // 持有股數  
  "avgCost": 650,                 // 平均成本  
  "currency": "TWD",  
  "currentPrice": 780,            // 由「同步股價」按鈕更新的快取價格  
  "updatedAt": timestamp  
}  
3\. monthlyConfigs (集合)  
儲存「每月定期定額」的公式模板。  
Document ID: {userId} (每個用戶存一筆，若有多種組合可再分)  
Fields:  欄位：  
code  
JSON  
{  
  "uid": "{userId}",  
  "configName": "穩健增長組合",  
  "items": \[  
    {  
      "category": "美股",  
      "ticker": "VOO",  
      "amount": 500,              // 投資金額  
      "currency": "USD"  
    },  
    {  
      "category": "台股",  
      "ticker": "0050.TW",  
      "amount": 10000,  
      "currency": "TWD"  
    }  
  \],  
  "updatedAt": timestamp  
}  
4\. snapshots (集合) \- 這是歷史軌跡的核心  
系統每月 1 號自動生成，或在有變動時覆寫當月紀錄。  
Document ID: {userId}\_{YYYY\_MM} (例如: JingUID\_2024\_05)  
Fields:  欄位：  
code  
JSON  
{  
  "uid": "{userId}",  
  "yearMonth": "2024-05",  
  "totalValueInBase": 1250000,     // 以 baseCurrency 計算的總市值  
  "holdingsSnapshot": \[           // 紀錄當下所有持股，用於差異分析  
    { "ticker": "AAPL", "shares": 10, "price": 180, "subtotal": 1800 },  
    { "ticker": "2330.TW", "shares": 500, "price": 780, "subtotal": 390000 }  
  \],  
  "allocationSnapshot": \[         // 紀錄當下的每月定期定額配置  
    { "ticker": "VOO", "amount": 500, "currency": "USD" }  
  \],  
  "isAutoGenerated": true,  
  "createdAt": timestamp  
}  
5\. stockCache (集合) \- 全域快取 (選配)  
為了節省 API 呼叫次數，將抓取過的股價暫存。  
Document ID: {ticker} (例如: AAPL)  
文件識別碼:{ticker} (例如: AAPL)

Fields:  欄位：  
code  
JSON  
{  
  "price": 185.2,  
  "currency": "USD",  
  "lastFetchAt": timestamp  
}

提示 (Dev Tips)  
為什麼要這樣設計 Snapshots？  
歷史不可變性： 當你下個月修改了定期定額配置，舊的 Snapshot 依然保留當初的配置數據。這讓 Gemini 可以輕鬆對比：「你上個月配置 10% 在債券，這月調低到 5%，原因可能是...」。  
效能優化： 你不需要去計算過去每一天的加總，只要直接讀取這份 Snapshots 的數據就能畫出漂亮的成長曲線圖。  
安全性規則 (Security Rules)：  
在 Firebase Console 記得設定，確保使用者只能讀寫 uid 等於自己 request.auth.uid 的資料：  
code  
JavaScript  
match /holdings/{document} {  
  allow read, write: if request.auth \!= null && request.auth.uid \== resource.data.uid;  
}  
如何處理台股格式？  
在使用 yahoo-finance2 時，請記得在介面上引導使用者，台股需要加上後綴（如：2330.TW 或 0050.TWO），這樣 API 才能精確回報。  
處理「差異對照」的程式邏輯：  
當 UI 需要呈現「差異對照」時，你的前端只需要讀取 snapshots/{userId}\_{上個月} 與 snapshots/{userId}\_{這個月}。這兩個陣列一對比，shares 或 amount 的增減便一目了然。

\<補充\>  
專案需求規格 (優化與定案版)  
1\. 資料庫與歷史追蹤邏輯 (Snapshot Logic)  
自動快照機制： 系統於每月 1 號自動依據「定期定額公式」生成當月資產快照 (Snapshot)。  
覆寫邏輯： 當月內若手動調整配置，系統採「最後一次變更為準 (Last Write Wins)」自動更新當月 Snapshot，確保資料實時性且不產生冗餘。  
歷史軌跡分析： 支援跨月資料比對，作為「資產配置趨勢圖」與「AI 分析差異」的基礎數據。  
2\. 資產數據處理與視覺化 (Data & Visualization)  
混合幣別總覽： 提供「一鍵切換」多維度檢視圖表，包含：  
全資產總覽： 透過手動匯率換算後的全球資產佔比。  
分類檢視： 獨立檢視「台股」、「美股」、「其他投資」之分佈狀況。  
動態報價同步： 採用「手動觸發、本地快取」策略。點擊「同步現況」按鈕後，抓取最新股價並回存 Firestore，降低 API 請求頻率並提升二次載入速度。  
理財目標進度條： 實作視覺化 Progress Bar，追蹤當前總資產相對於「理財目標」的達成率。  
3\. AI 增強功能與互動 UX (AI & Interaction)  
智慧 Prompt 生成： 自動帶入「當前資產狀態」及「MoM (Month-over-Month) 月增減差異」數據。  
Smart Copy 體驗： 點擊「前往 Gemini」時，自動執行背景複製 (Clip-board copy) 並同步開啟分頁，最大化減少使用者操作阻力。  
Markdown 輸出： 支援將每月配置與庫存快速導出為標準 Markdown 格式，方便做個人理財筆記或存檔。

 Prompt 模板自動涵蓋以下四個面向：  
資產平衡 (Rebalancing)： 「我的美股佔比上月 40%，這月變成 45%，是否需要減少定期定額流入轉往其他類別？」  
風險集中度 (Concentration)： 「分析我目前的持股，科技股比例是否過高？請根據當前全球宏觀經濟提供警示。」  
成長動能 (Growth momentum)： 「根據我這一個月的資產變動與加碼情況，評估我的資產增長速度是否符合一般通膨對抗邏輯。」  
配置調整理由： 「根據我本月的操作，與上個月相比，請分析這種變動是『被動市值增加』還是『主動加碼』，並給予策略點評。」
